# [PR 121](https://github.com/vig-os/sync-issues-action/pull/121) feat: fetch images and other attachments from issues and PRs

## Summary

Adds an opt-in `sync-attachments` input (default `false`) that downloads attachments (images, videos, files) referenced in issue/PR bodies and comments to `<output-dir>/attachments/<uuid>.<ext>` and rewrites body URLs to relative paths, so the synced markdown tree is complete offline.

Closes #2 — see the [spike results](https://github.com/vig-os/sync-issues-action/issues/2#issuecomment-4993945552) for the investigation behind the mechanism.

## How it works

- Bodies are fetched with the `application/vnd.github.full+json` media type, so each response carries `body_html` alongside the raw markdown.
- In `body_html`, GitHub has already rewritten every attachment (modern `user-attachments/assets/<uuid>` and legacy `user-images` URLs alike) to a pre-signed JWT URL on `private-user-images.githubusercontent.com` that downloads with plain HTTP — uniformly for public and private repos. The JWT is valid ~5 min, so downloads happen inside the per-item sync loop.
- Attachments are stored once per asset UUID (free dedup across issues/comments, no path-traversal from attacker-controlled names); both `![...](url)` and `<img src>` forms are rewritten to `../attachments/<uuid>.<ext>`.
- Signed/expiring URLs are never written to disk, so `hasContentChanged` idempotency is preserved.
- Failed downloads warn and keep the original URL; the sync never fails on an attachment.
- Downloaded files are added to `modified-files`; `format-command` now receives only markdown files.
- Non-image file attachments (`user-attachments/files/...`) are downloaded directly, which works on public repos and may fail on private ones (no signed URL is emitted for them) — documented in the README.

## Testing

- 17 new unit tests (TDD: red commit → green commit) covering extraction, rewrite of all three URL shapes, dedup, skip-if-exists, `force-update`, failure policy, and `run()` wiring; 138/138 total pass.
- End-to-end: ran the built `dist/index.js` against vig-os/qx#136 (real attachment) — PNG downloaded byte-identical to a manual fetch, body rewritten to the relative path, and a second run is fully idempotent (no re-download, no rewrite).
- `just precommit`, `just verify-dist`, lint, and `tsc` all green.

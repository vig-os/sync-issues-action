# [PR 214](https://github.com/vig-os/sync-issues-action/pull/214) chore: tidy the 0.5.1 release notes

Two edits to the frozen `## [0.5.1] - TBD` section, ahead of undrafting #213.

**1. Remove a duplicated dependency bullet.** The hand-written entry

> **Renovate: update `eslint` from `10.8.0` to `10.8.1`** (#177)

predates `synthesize-bot-changelog`, which now emits the same PR inside the
coalesced `#### Dependencies` block as `eslint 10.8.0 -> 10.11.0` (#177, #186,
#190, #195, #202). The manual line is a strictly narrower duplicate of the
synthesized one, so it goes.

**2. Add a `### Fixed` entry for the refreshed bundle** (#211, PR #212). The
`Dependencies` block lists the version bumps, but not the fact that none of them
reached the artifact consumers actually run until this release: `dist/index.js`
had been byte-identical to v0.5.0 since that tag, still embedding
`@octokit/auth-app` 8.3.0 / `@octokit/core` 10.0.13 / `@octokit/request` 7.0.7.
That is the only consumer-visible change v0.5.1 carries, so it belongs in the
notes rather than being inferable from a dependency list.

The synthesizer owns only the `#### Dependencies` block and rebuilds it in place,
so neither edit is at risk of being overwritten if it re-runs at finalize.

No issue: `chore` is Refs-exempt and this is release-notes copy-editing within
the train.

# [PR 212](https://github.com/vig-os/sync-issues-action/pull/212) build(deps): refresh the dist bundle to match the lockfile

Closes #211

Regenerates the committed `dist/index.js` so the published bundle carries the
locked runtime dependencies instead of the v0.5.0 set:

| Bundled dependency | Before | After |
|---|---|---|
| `@octokit/auth-app` | 8.3.0 | 8.3.1 |
| `@octokit/core` | 10.0.13 | 10.0.16 |
| `@octokit/request` | 7.0.7 | 7.0.8 |

Also picks up the `@vercel/ncc` 0.44 -> 0.45 output change from #181.

No `src/`, `action.yml` or `README.md` change — this is purely the build
artifact catching up with `package-lock.json`. `dist-check.yml` only runs on PRs
to `release/**` and `main`, so Renovate's `dev`-targeted lockfile bumps left the
bundle behind; the drift would otherwise surface as a failing `Dist Check` on
the v0.5.1 release PR, which the train cannot clear on its own
(`release-core.yml`'s bundle rebuild is `final`-only and sits downstream of the
candidate's check gate — vig-os/devkit#1745).

Verified locally with the same sequence `dist-check.yml` runs:

```sh
npm ci && npm run bundle && git status --porcelain -- dist/   # clean after this commit
```
